# 意图识别、槽位设计、上下文记忆与指代消解

## 意图列表

### book_ticket

购票意图。用户想买电影票、订票、看电影、选座、查场次，都可以归为购票意图。

示例：

- 帮我订两张电影票。
- 明晚想看个喜剧。
- 流浪地球今晚还有票吗？
- 周末附近有啥好看的？
- 我要两张 IMAX。

### search_movie

查电影意图。用户只想了解或筛选电影，但不一定立刻购票。

示例：

- 最近有什么电影上映？
- 有什么评分高的喜剧？
- 介绍一下这部电影。

### search_showtime

查场次意图。用户关心时间、影院和票价。

示例：

- 今晚 8 点后还有什么场次？
- 万达影城今天还有 IMAX 吗？
- 便宜点的场次有哪些？

### select_or_modify

选择或修改意图。用户基于当前卡片或上下文做选择。

示例：

- 选第一个。
- 换便宜点。
- 换一家。
- 晚一点。
- 还是老位置。
- 不要这个。

### order_query

订单查询意图。

示例：

- 查一下我的订单。
- 我刚刚买的票在哪？
- 我的票取票码是多少？

### refund_policy

退票、改签、取消订单规则咨询。

示例：

- 可以退票吗？
- 怎么改签？
- 支付后还能取消吗？

### faq

常见问题咨询。

示例：

- IMAX 是什么？
- 情侣座是什么？
- 儿童需要买票吗？
- 影院停车方便吗？

### admin_query

B 端经营分析或管理意图。

示例：

- 今天哪个电影卖得最好？
- 哪个时间段订单最多？
- 帮我分析一下今天票房。

## 核心槽位

推荐槽位结构：

```json
{
  "movieId": null,
  "movieName": null,
  "genre": null,
  "date": null,
  "timeRange": null,
  "city": null,
  "location": null,
  "cinemaId": null,
  "cinemaName": null,
  "hallType": null,
  "ticketCount": null,
  "pricePreference": null,
  "seatPreference": null,
  "showtimeId": null,
  "seatIds": null,
  "orderId": null
}
```

## 槽位解释

- `movieId`：电影唯一 ID，来自业务后端。
- `movieName`：电影名称，如“流浪地球 3”。
- `genre`：电影类型，如喜剧、科幻、爱情、动画、悬疑。
- `date`：观影日期，如今天、明天、周末、2026-08-01。
- `timeRange`：观影时间段，如上午、下午、晚上、8 点后。
- `city`：城市，可来自用户定位或默认城市。
- `location`：位置偏好，如公司附近、学校附近、离我近。
- `cinemaId`：影院唯一 ID。
- `cinemaName`：影院名称，如万达影城。
- `hallType`：影厅类型，如 IMAX、巨幕、杜比、普通厅。
- `ticketCount`：票数。
- `pricePreference`：价格偏好，如 cheap、normal、best。
- `seatPreference`：座位偏好，如 middle、couple、front、back、old_position。
- `showtimeId`：场次唯一 ID。
- `seatIds`：选择的座位 ID。
- `orderId`：订单 ID。

## 常见表达映射

### 时间表达

- “今晚”：今天 18:00 到 23:59。
- “明晚”：明天 18:00 到 23:59。
- “下午”：12:00 到 18:00。
- “晚上”：18:00 到 23:59。
- “8 点后”：20:00 之后。
- “周末”：最近一个周六和周日。
- “下班后”：默认 18:30 之后。

### 价格表达

- “便宜点”：优先低价，`pricePreference = cheap`。
- “性价比高”：价格和评分综合排序。
- “贵一点也行”：优先位置、厅型或评分。
- “30 元以下”：设置最高票价。

### 距离表达

- “附近”：优先距离近。
- “离公司近”：使用用户档案中的公司地址。
- “离学校近”：使用用户档案中的学校地址。
- “换一家”：基于当前影院排除后重新推荐。

### 座位表达

- “中间”：优先中区居中。
- “靠后”：优先后排。
- “不要太前”：排除前三排。
- “情侣座”：优先情侣座区域。
- “连座”：必须选择相邻座位。
- “老位置”：读取历史偏好，通常是中后排居中连座。

## 上下文记忆

Agent 应按 `sessionId` 保存当前会话上下文，至少包含：

- 当前状态。
- 当前槽位。
- 最近一次卡片列表。
- 最近一次候选场次列表。
- 最近一次候选影院列表。
- 最近一次座位图。
- 用户已选择但未支付的订单。

## 用户偏好记忆

用户偏好可以来自 Mock 数据或历史订单：

- 常看电影类型。
- 常去影院。
- 常用观影时间。
- 常买票数。
- 常选座位区域。
- 价格敏感度。
- 是否偏好 IMAX 或杜比厅。

示例用户画像：

```json
{
  "userId": "u001",
  "favoriteGenres": ["科幻", "动作"],
  "preferredCinema": "万达影城",
  "seatPreference": "middle",
  "pricePreference": "normal",
  "usualTicketCount": 2
}
```

## 指代消解规则

### “第一个”“第二个”

根据当前最近展示的卡片类型解析。

- 当前展示影片卡片：指第几个影片。
- 当前展示影院卡片：指第几个影院。
- 当前展示场次卡片：指第几个场次。
- 当前展示座位推荐卡片：指第几个座位方案。

### “这个”“那个”

优先指向用户最近点击或 Agent 最近重点推荐的对象。

### “换一家”

如果当前已有影院，表示排除当前影院，重新推荐其他影院或场次。

### “换便宜点”

如果当前在场次选择阶段，重新筛选更低价场次。

如果当前在座位选择阶段，优先查找同场次低价区域；若同场次无差价，则推荐更便宜的场次。

### “还是老位置”

读取用户历史座位偏好。如果没有历史记录，默认解释为中后排居中连座，并说明“我先按中后排居中给您找”。

## 置信度策略

如果 NLU 识别置信度高于 0.75，可以直接执行下一步。

如果置信度在 0.45 到 0.75 之间，应给出带确认的推荐。

如果置信度低于 0.45，应追问澄清。

示例：

用户：“想看点轻松的。”

Agent 可以理解为喜剧、动画、爱情轻喜剧等轻松类型，但不应直接下单，应推荐类型或影片让用户确认。
