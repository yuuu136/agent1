# Agent 工作流、任务规划与自动跳步

## Agent 核心原则

电影票智能体的核心不是“按固定流程问问题”，而是“根据用户已经提供的信息动态决定下一步”。每次用户输入文本或点击卡片后，Agent 都要重新检查当前槽位是否完整，然后决定追问、查询、推荐、跳转、锁座或下单。

## Agent 总流程

```text
接收输入
-> 识别输入类型：文本或卡片事件
-> 意图识别
-> 槽位提取
-> 上下文合并
-> 指代消解
-> 槽位完整度检查
-> 任务规划
-> 调用业务工具或 RAG
-> 生成文本回复
-> 生成动态卡片
-> 返回给前端
```

## 自动跳步定义

自动跳步是指 Agent 不按固定页面流程逐个询问，而是根据已知槽位直接进入最合适的业务步骤。

例如用户说：“帮我订两张明晚 8 点万达 IMAX 的《流浪地球 3》。”

已包含：

- 电影名。
- 日期。
- 时间。
- 影院。
- 影厅类型。
- 票数。

Agent 不应该再问“想看什么电影”或“去哪家影院”，而应直接查询符合条件的场次，并推送场次卡片或座位卡片。

## 缺槽追问原则

只有缺少关键槽位且无法合理默认时，Agent 才追问。

关键槽位通常包括：

- 观影对象：电影名或类型至少有一个。
- 时间范围：今天、明天、周末、晚上等。
- 票数。
- 场次或影院信息。
- 座位选择。

可以默认的槽位：

- 城市：默认当前城市或用户档案城市。
- 影院：可默认推荐附近影院。
- 座位偏好：可默认中后排居中连座。
- 价格偏好：可默认综合推荐。

## 状态机

推荐状态包括：

```text
idle                空闲状态
collecting_slots    收集购票条件
choosing_movie      推荐或选择影片
choosing_cinema     推荐或选择影院
choosing_showtime   推荐或选择场次
choosing_seats      推荐或选择座位
confirming_order    确认订单
paying              模拟支付
ticket_issued       已出票
order_query         查询订单
faq_answering       规则问答
exception_handling  异常处理
```

状态机用于管理对话上下文，但最终执行动作应由槽位检查器决定，不能被固定状态限制。

## 槽位检查器规则

槽位检查器每轮都判断：

- 是否有明确购票意图。
- 是否已有电影名或电影类型。
- 是否已有日期或时间范围。
- 是否已有票数。
- 是否已有场次。
- 是否已有座位。
- 是否已有订单确认。

推荐决策：

```text
没有购票意图 -> 判断是否 FAQ、查订单或闲聊
有购票意图但无电影名和类型 -> 追问影片或类型
有类型但无具体电影 -> 搜索并推荐影片
有电影或类型但无场次 -> 搜索场次
有多个场次候选 -> 推送场次卡片
有唯一高置信场次且票数明确 -> 推送座位卡片
有座位 -> 锁座并生成订单确认
用户确认支付 -> 调用支付并出票
```

## 自动跳步示例

### 信息缺失

用户：“想看流浪地球。”

Agent 判断：有电影名，但缺少时间、票数、影院偏好。

Agent 回复：“可以，我先帮您找《流浪地球》的场次。您想今天看、明天看，还是周末看？如果不确定，我也可以直接推荐最近的热门场次。”

### 信息基本完整

用户：“帮我订两张明晚 8 点后的喜剧片，便宜点。”

Agent 判断：有类型、日期、时间、票数、价格偏好，缺具体影片和影院，但可以自动搜索。

Agent 动作：调用场次搜索工具，按价格、评分、距离综合排序，返回场次卡片。

Agent 回复：“我按明晚 8 点后、两张、喜剧、价格优先帮您筛好了，第一场性价比最高。”

### 信息溢出

用户：“帮我订两张明晚 8 点万达影城 IMAX《流浪地球 3》，座位要中间。”

Agent 判断：槽位充分。

Agent 动作：直接查对应场次和座位，推荐中区连座，不再逐步追问。

Agent 回复：“我找到了符合条件的 IMAX 场次，并优先为您挑了中区连座。”

## 用户修正条件

用户可能在任何阶段修改条件。Agent 应更新槽位并回退到必要步骤。

示例：

- “换便宜点”：更新价格偏好，重新筛选场次或座位。
- “换一家”：更新影院选择，重新查场次。
- “晚一点”：更新时间范围，重新查场次。
- “不要 IMAX”：移除影厅类型，重新查场次。
- “只要连座”：更新座位偏好，重新推荐座位。

## 卡片事件处理

前端点击卡片后，应以事件形式发送给 Agent。Agent 将事件转为槽位更新。

事件示例：

- `select_movie`：更新 `movieId` 和 `movieName`。
- `select_cinema`：更新 `cinemaId`。
- `select_showtime`：更新 `showtimeId`。
- `select_seats`：更新 `seatIds`。
- `confirm_order`：进入支付。
- `pay_order`：调用支付和出票。

## RAG 在工作流中的位置

当用户问规则、说明、推荐理由或服务问题时，Agent 可以调用 RAG。

示例：

- “IMAX 和普通厅有什么区别？”
- “为什么推荐这个座位？”
- “可以退票吗？”
- “优惠券怎么用？”

当用户需要实时购票动作时，Agent 必须调用 Spring Boot 业务工具。
