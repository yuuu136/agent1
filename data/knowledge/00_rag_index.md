# 电影票智能体 RAG 知识库总索引

## 知识库定位

本知识库用于电影票智能体系统的 RAG 检索增强。它提供稳定的业务知识、交互规范、推荐策略、异常处理话术、常见问答和演示案例。

RAG 只用于回答和解释相对稳定的信息，不用于决定实时库存、锁座、下单、支付和出票。实时业务数据必须通过 Spring Boot 后端业务接口查询。

## RAG 可以回答的问题

- 系统是什么，智能体购票和传统购票有什么区别。
- 用户说一句话后，Agent 应该如何理解、追问、跳步和推荐。
- 电影、影院、场次、座位、订单卡片应该展示什么字段。
- 用户说“换便宜点”“换一家”“还是老位置”“第二个”时如何理解。
- 座位被抢、场次售罄、价格过高、信息缺失时如何温柔处理。
- 退改签、优惠券、会员价、儿童票、情侣座、IMAX 等规则如何解释。
- 项目答辩时如何展示核心链路和创新点。

## RAG 不应该回答或决定的问题

- 某个场次当前是否还有座位。
- 某个座位是否已经被锁定。
- 是否创建订单成功。
- 是否支付成功。
- 是否出票成功。
- 某个用户的真实订单信息。
- 某个用户的真实手机号、支付信息等隐私数据。

遇到这些问题，Agent 应调用业务工具接口，而不是依赖知识库文本。

## 检索建议

建议按 Markdown 标题切片，每个 chunk 保留 frontmatter 元数据。推荐 chunk 大小为 500 到 900 个中文字符，重叠 80 到 150 个中文字符。

当用户问题涉及实时业务，RAG 结果只能作为解释补充，最终结论必须由工具调用结果决定。
