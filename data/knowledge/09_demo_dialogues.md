# 演示对话与测试用例

## 演示目标

演示时应突出：

- 一句话表达需求。
- 自动跳步。
- 动态卡片。
- 多轮上下文。
- 锁座、下单、支付、出票闭环。
- 异常处理有温度。

## 用例 1：一句话买票

用户：“帮我订两张明晚 8 点后附近便宜点的喜剧片。”

Agent 识别：

- 意图：购票。
- 类型：喜剧。
- 时间：明晚 8 点后。
- 票数：2。
- 位置：附近。
- 价格偏好：便宜。

Agent 动作：

- 查询符合条件的场次。
- 按价格、距离、评分排序。
- 推送场次卡片。

Agent 回复：

“我按明晚 8 点后、两张、附近、便宜优先帮您筛好了。第一场最省钱，第二场距离最近。”

## 用例 2：信息缺失追问

用户：“想看流浪地球。”

Agent 识别：

- 电影：流浪地球。
- 缺时间、票数、影院。

Agent 回复：

“可以，我帮您找《流浪地球》的场次。您想今天看、明天看，还是周末看？需要几张票？”

## 用例 3：自动跳到座位

用户：“两张明晚 8 点万达 IMAX《流浪地球 3》，座位要中间。”

Agent 识别：

- 电影、时间、影院、影厅类型、票数、座位偏好都完整。

Agent 动作：

- 查询场次。
- 如果唯一匹配，直接查座位。
- 推送座位图卡片。

Agent 回复：

“找到万达影城明晚 8 点后的 IMAX 场次了。我直接为您挑了中区两个连座，您可以确认或手动换座。”

## 用例 4：换便宜点

用户先选中 IMAX 场次。

用户：“太贵了，换便宜点。”

Agent 动作：

- 保留电影、日期、票数。
- 降低影厅要求或扩大影院范围。
- 重新搜索低价场次。

Agent 回复：

“可以。我保留电影和时间，把 IMAX 条件放宽后，找到一场普通厅，两张能省 36 元。”

## 用例 5：指代“第二个”

Agent 展示 3 个场次卡片。

用户：“选第二个。”

Agent 动作：

- 从最近场次卡片列表中取第 2 个场次。
- 更新 `showtimeId`。
- 查询座位图。

Agent 回复：

“好的，已选择第二个场次。我现在为您加载座位图。”

## 用例 6：还是老位置

用户：“还是老位置。”

Agent 动作：

- 查询用户偏好或历史订单。
- 获取常选座位区域。
- 推荐相似座位。

Agent 回复：

“我按您之前常选的中后排居中连座来找，这两个位置视角比较接近老位置。”

## 用例 7：座位被抢

用户选择 6 排 7、8 座。

锁座失败，后端返回座位已被锁。

Agent 动作：

- 重新获取座位图。
- 推荐相邻连座。

Agent 回复：

“手慢了一点，刚才的位置被锁走了。不过同一排旁边还有两个连座，视角很接近，我帮您标出来了。”

## 用例 8：场次售罄

用户选择某个热门场次。

后端返回场次售罄。

Agent 回复：

“这场已经满座了。我给您找了两个替代方案：同影院 20 分钟后的场次，或者 1.2 公里外影院的相近时间场次。”

## 用例 9：退票咨询

用户：“我买完后可以退吗？”

Agent 回答：

“是否支持退票要看影院和票种规则。未支付订单可以直接取消；已支付订单需要看距离开场时间、活动票规则和影院政策。我可以帮您先查订单详情。”

## 用例 10：B 端经营分析

管理员：“今天哪个电影卖得最好？”

Agent 动作：

- 调用后端销售统计接口。
- 按票房或订单数排序。

Agent 回复：

“按已支付订单票房统计，今天销售最好的是《流浪地球 3》。如果按订单数统计，第一名也是它，共售出 128 张。”

## 测试清单

必须测试：

- 文本购票入口。
- 卡片点击事件。
- 自动跳步。
- 缺槽追问。
- 修改条件。
- 指代消解。
- 座位锁定。
- 订单创建。
- 模拟支付。
- 出票。
- 座位被抢。
- 场次售罄。
- 退改签 FAQ。
