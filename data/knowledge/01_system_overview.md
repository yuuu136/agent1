# 电影票智能体系统总览

## 系统一句话介绍

电影票智能体系统是一个通过“纯文本对话 + 动态卡片”完成电影购票的智能系统。用户不需要像传统电影购票 App 一样在多个页面之间反复筛选，而是可以用一句自然语言表达需求，例如“帮我订两张明晚 8 点后附近便宜点的喜剧片”。Agent 会理解需求、补全缺失信息、调用业务接口、推荐场次和座位，并最终完成锁座、下单、模拟支付和出票。

## 系统目标

系统目标不是简单复刻传统购票平台，而是突出智能体能力：

- 听懂用户模糊表达。
- 从一句话中抽取多个购票条件。
- 根据槽位完整度自动跳过不必要步骤。
- 信息缺失时自然追问。
- 信息过多时直接执行下一步。
- 结合动态卡片完成可视化选择。
- 在异常场景下提供有温度的替代方案。

## 用户角色

### C 端用户

C 端用户通过 H5 页面使用系统。主要操作包括：

- 输入购票需求。
- 查看 Agent 文本回复。
- 点击影片卡片、影院卡片、场次卡片、座位卡片。
- 确认订单。
- 模拟支付。
- 查看出票结果。
- 查询订单和退改签规则。

### B 端管理员

B 端管理员通过后台管理电影票业务数据。主要操作包括：

- 电影管理。
- 影院管理。
- 影厅管理。
- 座位管理。
- 排片管理。
- 订单管理。
- 查看销售数据。
- 维护优惠活动和影院规则。

### Agent 智能体

Agent 是系统核心。它负责：

- 意图识别。
- 槽位提取。
- 上下文记忆。
- 指代消解。
- 任务规划。
- 自动跳步。
- 调用业务工具接口。
- 生成动态卡片。
- 生成自然语言回复。
- 异常处理和替代推荐。

## 推荐技术架构

前端使用 React：

- C 端 H5：React + Vite + TypeScript + Ant Design Mobile。
- B 端后台：React + Vite + TypeScript + Ant Design。

Agent 使用 Python：

- Python + FastAPI。
- Agent 状态机、槽位提取、RAG 检索、业务工具调用。

业务后端使用 Spring Boot：

- 用户、电影、影院、影厅、排片、座位、订单、支付模拟、出票。
- MySQL 保存业务数据。
- Redis 可用于座位锁和订单超时释放。

推荐调用链：

```text
React H5
  -> Spring Boot
  -> Python Agent
  -> Spring Boot 业务工具接口
  -> MySQL / Redis
```

也可以在 MVP 阶段让 React H5 直接调用 Python Agent，但正式联调建议经过 Spring Boot，便于统一鉴权、日志和接口管理。

## 核心业务闭环

必须跑通以下完整流程：

```text
用户表达需求
-> Agent 识别意图和槽位
-> Agent 判断是否缺信息
-> Agent 查询电影/影院/场次
-> Agent 推送动态卡片
-> 用户选择场次或座位
-> Agent 调用锁座接口
-> Agent 创建订单
-> 用户确认订单
-> 模拟支付
-> 出票成功
```

这个闭环是评分重点。只做聊天问答但不能买票，不算完整智能购票系统。

## 系统边界

Agent 不能直接操作数据库。Agent 只通过 Spring Boot 提供的业务工具接口完成查电影、查场次、查座位、锁座、下单、支付和出票。

Agent 可以使用 RAG 知识库解释业务规则、退改签说明、优惠活动、影院服务和推荐理由。

Agent 不能用 RAG 文档判断实时座位是否可买。实时数据必须调用业务接口。

## 典型用户入口话术

用户可能这样表达需求：

- 帮我订两张明晚 8 点后的喜剧片。
- 周末想看个科幻，最好是 IMAX。
- 离公司近一点，价格别太贵。
- 想看流浪地球，今晚还有票吗？
- 换便宜点。
- 换一家影院。
- 还是老位置。
- 选第二个。
- 帮我查一下我的订单。

Agent 应结合当前对话状态判断用户是在发起新任务、修改条件、选择卡片、查询订单还是咨询规则。
