# 电影票业务规则、锁座、订单、支付与出票

## 业务数据对象

### Movie 电影

包含电影名称、类型、时长、评分、海报、简介、上映状态、标签。

### Cinema 影院

包含影院名称、地址、经纬度、服务设施、最低票价、联系电话。

### Hall 影厅

包含影厅名称、影厅类型、座位布局、屏幕位置。

影厅类型包括：

- 普通厅。
- IMAX。
- 巨幕厅。
- 杜比厅。
- VIP 厅。

### Seat 座位

包含座位 ID、行号、列号、座位标签、座位类型、是否可用。

座位类型包括：

- 普通座。
- 情侣座。
- VIP 座。
- 无障碍座。

### Showtime 场次

包含电影、影院、影厅、开始时间、结束时间、票价、剩余座位数。

### Order 订单

包含用户、场次、座位、订单金额、订单状态、锁座过期时间、支付状态、出票状态。

## 订单状态

推荐订单状态：

```text
pending_lock     待锁座
locked           已锁座待确认
pending_payment  待支付
paid             已支付
ticket_issued    已出票
cancelled        已取消
expired          已超时
refund_pending   退款中
refunded         已退款
```

## 座位状态

```text
available  可选
locked     已锁定
sold       已售
disabled   不可售
```

座位锁定是临时状态。支付成功后，座位从 `locked` 变为 `sold`。订单超时或取消后，座位从 `locked` 回到 `available`。

## 锁座规则

锁座用于防止超卖。用户选择座位后，系统应先锁定座位，再创建待支付订单。

锁座规则：

- 同一场次同一座位只能被一个订单锁定。
- 锁座应有过期时间，推荐 15 分钟。
- 支付成功前，座位显示为已锁定。
- 订单取消或超时未支付，应释放座位。
- 锁座失败时，应重新获取最新座位图并推荐替代座位。

## 支付规则

MVP 阶段采用模拟支付。用户点击支付按钮后，后端直接将订单状态改为已支付。

支付成功后：

- 订单状态变为 `paid`。
- 座位状态变为 `sold`。
- 触发出票。

支付失败时：

- 保持订单待支付。
- 告知用户可重试。
- 若超过锁座时间，订单过期并释放座位。

## 出票规则

出票成功后，系统生成：

- 票据 ID。
- 订单 ID。
- 电影名称。
- 影院。
- 影厅。
- 座位。
- 开场时间。
- 取票码或二维码。

MVP 可使用模拟取票码，例如 `TK202607280001`。

## 票数规则

用户未说明票数时：

- 如果用户历史常买票数存在，可默认建议。
- 否则追问“您需要几张票？”

常见表达：

- “两张” -> `ticketCount = 2`。
- “我和朋友” -> 通常推断 2 张，但建议确认。
- “我们三个人” -> `ticketCount = 3`。

## 连座规则

多人购票时，应优先推荐连座。若无连座，应告知用户并推荐最接近座位组合。

示例话术：

“这场已经没有完全连在一起的 3 个座位了。我找到两个比较近的方案：一个是同排隔一个座，另一个是前后排相邻，您更接受哪个？”

## 座位推荐规则

默认座位推荐优先级：

1. 连座。
2. 中后排。
3. 靠近中轴线。
4. 避开第一排和边角。
5. 避开已售座位密集区域。

如果用户指定偏好，以用户偏好优先。

## 场次推荐规则

默认场次推荐综合考虑：

- 时间匹配度。
- 距离。
- 价格。
- 电影评分。
- 影厅类型。
- 剩余座位。
- 是否满足连座。

如果用户说“便宜点”，价格权重提高。

如果用户说“近一点”，距离权重提高。

如果用户说“效果好一点”，影厅类型和座位质量权重提高。

## 退改签规则

MVP 阶段可以只做规则说明，不做真实退款。

建议规则：

- 未支付订单可直接取消。
- 已支付订单是否可退，以影院规则为准。
- 距开场时间太近时可能无法退改。
- 特价票、活动票可能不支持退改。

Agent 回答退改签时，应提醒用户查看订单卡片或具体影院规则。

## 业务工具接口建议

Agent 应调用 Spring Boot 提供的业务接口：

```text
GET  /internal/movies/search
GET  /internal/cinemas/search
GET  /internal/showtimes/search
GET  /internal/showtimes/{showtimeId}/seats
POST /internal/seats/lock
POST /internal/orders
POST /internal/orders/{orderId}/pay
GET  /internal/orders/{orderId}
GET  /internal/users/{userId}/preferences
```

Agent 不能直接改数据库。所有库存、订单和支付状态必须由 Spring Boot 业务后端处理。
